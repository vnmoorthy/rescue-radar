# Rescue Radar API and data contract

This is the contract between the backend (`rr/server.py`), the dispatch console (`web/`), the static
demo export (`docs/`), the docs and the deck. Everything reads the same files and endpoints.

## Repository layout

| Path | Owner | What it is |
| --- | --- | --- |
| `rr/labels.py` | core | The 10 HumAID categories, `RESCUE_CRITICAL`, the single prompt every system gets |
| `rr/prep.py` | core | Builds the held-out-disaster split |
| `rr/train.py` | core | LoRA fine-tune on Fireworks serverless training |
| `rr/infer.py` | core | `SamplerClassifier` (the code path the benchmark and the live server share) and `get_classifier()` |
| `rr/frontier.py` | core | `classify_frontier(text)`: live Claude Opus 5.5 baseline call |
| `rr/evaluate.py` | core | Scores every system, writes `results/metrics.json` |
| `rr/server.py` | backend | FastAPI app, serves `/api/*` and the console at `/` |
| `rr/geo.py` | backend | Gazetteer: place names in posts -> lat/lng |
| `rr/scrub.py` | backend | PII redaction before a human sees a post |
| `web/` | frontend | The dispatch console (no build step) |
| `docs/` | static | GitHub Pages: static console + deck, generated by `scripts/export_static.py` |
| `data/` | core | `eval.jsonl`, `test_full.jsonl`, `preds/*.jsonl`, training logs (generated, not hand edited) |
| `results/metrics.json` | core | Benchmark results (schema below) |

Never read, print or commit `.env`. Load secrets only through `rr.env.load_env()`.

## Data files

`data/eval.jsonl`: the shared held-out eval set, 3,001 tweets from 4 unseen 2019 disasters.
```json
{"id": "1168139805810728960", "event": "hurricane_dorian_2019", "text": "...", "label": "caution_and_advice"}
```
`id` is a Twitter snowflake. Post time in ms = `(int(id) >> 22) + 1288834974657`. Use it to order a replay.

`data/test_full.jsonl`: same shape, all 15,384 test tweets.

`data/preds/<system>.jsonl`: one row per eval tweet. Systems: `opus_zero`, `opus_few` (frontier),
`base_zero` (Nemotron before fine-tuning), `rescue_radar` (ours, fine-tuned).
```json
{"id": "...", "event": "...", "label": "<true>", "pred": "<predicted>", "raw": "<model text>", "latency": 1.22, "in_tok": 444, "out_tok": 14}
```
`latency` is seconds. `in_tok`/`out_tok` may be missing for systems served without token accounting.

`data/train_log.jsonl`: `{"step": 1, "loss": 58.8, "secs": 6.9, "at": "13:40:35"}` per training step.

## Labels

From `rr.labels`: `LABELS` (id -> one-line definition), `RESCUE_CRITICAL` =
`{requests_or_urgent_needs, injured_or_dead_people, missing_or_found_people}`.
Display names: replace `_` with spaces and capitalize. Suggested colors are the frontend's choice, but
rescue-critical categories must read as urgent (red/orange family) in both themes.

## Python interfaces (core, already implemented)

```python
from rr.infer import get_classifier
clf = get_classifier()        # cached singleton
clf.name                      # e.g. "Rescue Radar: Nemotron 3.5 Super + LoRA"
clf.kind                      # "finetuned" | "base"
clf.classify(["post 1", "post 2"])  # -> [{"label": "requests_or_urgent_needs", "latency_ms": 312.5, "raw": "..."}]

from rr.frontier import classify_frontier, FRONTIER_NAME
classify_frontier("post")     # -> {"label": ..., "latency_ms": ..., "in_tok": ..., "out_tok": ..., "cost_usd": ...}
```
Both raise `RuntimeError` with a readable message if the model is unavailable. The server must turn that
into an HTTP 503 with `{"detail": "<message>"}`, never a crash.

**Which weights the live server serves** (`rr/server.py` `live_target()`; `RR_LIVE_MODEL` is read only by the server,
never by `rr.run_model` or `rr.promote`): unset or `scored` = the checkpoint recorded in
`data/preds/<ours>.meta.json` for the replay's "ours" system (below), i.e. exactly what the benchmark scored, followed
without a restart when that system changes; `<system>` = that scored system's checkpoint; `latest` =
`rr.infer.get_classifier()` (`data/active_model.json`, else the newest training checkpoint, which may be unscored).
`RR_MODE=base` serves the untuned base model.

## HTTP API (backend implements, frontend consumes)

All JSON. Errors: `{"detail": str}` with a 4xx/5xx status, including request validation (422): the detail is a
`"field: message; ..."` string and never echoes the input back.

| Method | Path | Returns |
| --- | --- | --- |
| GET | `/api/health` | `{"ok": true, "model": {"name","kind","ready","loaded","error","scored","system","step"}, "frontier": {"name","ready"}}` (`scored`: the live weights are exactly that scored `system`'s checkpoint) |
| GET | `/api/meta` | `{"labels":[{"id","name","definition","critical"}], "events":[Event], "model":{"name","kind","scored","system","step"}, "frontier":{"name"}, "training":{"system","examples","batch","steps","source"}|null, "static": false}` (`training` is read from the headline run's log header, `data/train.out` or `data/train_full.out`) |
| GET | `/api/replay/{event_id}` | `{"event": Event, "posts": [ReplayPost]}` sorted by `ts` |
| POST | `/api/classify` | body `{"text"}` -> `Classified` |
| POST | `/api/classify_batch` | body `{"texts": [..]}` (max 200) -> `{"results": [Classified], "total_ms"}` |
| POST | `/api/compare` | body `{"text"}` -> `{"ours": Classified, "frontier": FrontierResult}` |
| GET | `/api/queue` | `{"items": [QueueItem]}` newest first |
| POST | `/api/queue` | body `{"post_id","text","label","event","place"}` -> `QueueItem` (idempotent on `post_id`). `text` is required and non-empty; `post_id` a string (max 200) or integer; `label` one of the 10 ids or null; `event` a known event id or null; `place` `{"name" (max 200), "lat" (-90..90), "lng" (-180..180)}` with finite numbers, or null (then it is looked up from the redacted text). Anything else -> 422 |
| PATCH | `/api/queue/{qid}` | body `{"status": "open"|"dispatched"|"resolved"|"dismissed", "note"?}` -> `QueueItem`; `qid` must be 1..2^63-1 (422 otherwise), 404 if absent |
| DELETE | `/api/queue` | clears the queue -> `{"ok": true}` |
| GET | `/api/queue.csv` | CSV download of the queue (UTF-8 with a byte-order mark, so Excel reads non-ASCII text) |
| GET | `/api/results` | contents of `results/metrics.json` (NaN/Infinity read as null), or `{"status": "pending"}` |
| GET | `/api/train_log` | `{"runs": {"<tag>": [ {"step","loss","secs","at"} ]}}` (rows with a missing or non-finite step/loss are skipped) |
| GET | `/data/*` | the static export (`docs/data/`), so the console's recorded-data fallback matches the last export |

Types:
```text
Event         {"id","name","type","year","country","center":[lat,lng],"zoom","n_posts","n_critical"}
ReplayPost    {"id","ts","text","place":{"name","lat","lng"}|null,"truth","truth_critical",
               "ours":{"label","critical","latency_ms"}|null,
               "frontier":{"label","critical","latency_ms","cost_usd"}|null}
Classified    {"label","label_name","critical","latency_ms","model","redacted_text","redactions":[{"type","start","end"}],"place"}
FrontierResult{"label","label_name","critical","latency_ms","cost_usd","model"}
QueueItem     {"qid","post_id","text","label","event","place","status","note","created_at","updated_at"}
```
`ReplayPost.text` is already PII-scrubbed and HTML-entity decoded, and `place` is looked up from that redacted text.
`ours`/`frontier` come from `data/preds/rescue_radar.jsonl` once that file is **complete** (its
`rescue_radar.meta.json` exists, which `rr.run_model` writes after the last chunk, or it has a row for every eval
post), else `rescue_radar_quick.jsonl`, and from `data/preds/opus_few.jsonl`; `null` if that file has no row for the
post. (`rr/evaluate.py` still picks `headline.ours` by file existence with at least 500 rows; its owner should apply
the same completeness rule so the replay and the benchmark can never describe different runs.)
`scripts/export_static.py` refuses to export (exit 1) while results are pending or any replay's `coverage.ours` is
below its post count (`--allow-partial` overrides for local previews). The replay response also carries `"systems": {"ours": "<preds file>", "frontier": "opus_few"}` and
`"coverage": {"ours": n, "frontier": n}`.

## results/metrics.json (written by `rr/evaluate.py`)

```json
{
  "generated_at": "2026-11-02T14:40:00",
  "eval": {"n": 3001, "events": {"hurricane_dorian_2019": 1485}, "train_events": 15, "test_events": 4,
           "train_examples": 3839, "split": "train on 2016-2018 disasters, test on 4 unseen 2019 disasters"},
  "systems": {
    "rescue_radar": {
      "name": "Rescue Radar (Nemotron 3.5 Super + LoRA)", "kind": "open-finetuned", "model": "accounts/...",
      "accuracy": 0.81, "macro_f1": 0.70,
      "critical": {"precision": 0.80, "recall": 0.85, "f1": 0.82},
      "ci95": {"accuracy": [0.79, 0.83], "macro_f1": [0.67, 0.73], "critical_recall": [0.80, 0.89]},
      "latency_ms": {"p50": 300, "p95": 600, "mean": 350},
      "cost_per_1m_usd": 120.0, "cost_note": "measured|estimated: ...",
      "per_event": {"hurricane_dorian_2019": {"n": 1485, "accuracy": 0.8, "macro_f1": 0.7, "critical_recall": 0.9}},
      "per_class": {"requests_or_urgent_needs": {"precision": 0.7, "recall": 0.8, "f1": 0.75, "support": 78}},
      "confusion": {"labels": ["..."], "matrix": [[0]]}
    }
  },
  "comparisons": [
    {"a": "rescue_radar", "b": "opus_few", "n": 2592, "metric": "accuracy",
     "a_on_shared": {"accuracy": 0.81, "macro_f1": 0.70, "critical_recall": 0.85},
     "b_on_shared": {"accuracy": 0.69, "macro_f1": 0.62, "critical_recall": 0.70},
     "delta": 0.12, "delta_macro_f1": 0.08, "delta_critical_recall": 0.15,
     "mcnemar": {"a_only": 400, "b_only": 50, "p": 1e-20},
     "bootstrap": {"delta_ci95": [0.10, 0.14], "macro_f1_delta_ci95": [0.05, 0.11],
                   "critical_recall_delta_ci95": [0.09, 0.21], "a_wins": 5000, "n": 5000,
                   "unit": "tweet, resampled within each disaster"}}
  ],
  "headline": {"ours": "rescue_radar", "frontier": "opus_few"}
}
```
`comparisons` has one entry per pair of systems (`a` is always `headline.ours`), paired on the `n` posts both
answered: `delta` is the accuracy gap, `delta_macro_f1` / `delta_critical_recall` the other two, each with its own
`*_delta_ci95`, and `bootstrap.a_wins` counts resamples where `a` has the higher **macro-F1**. Systems with partial
coverage carry `n`, `coverage` (0-1) and `coverage_note`. (The numbers above are illustrative, not results.)
Consumers must tolerate missing systems and missing fields (show "n/a"), because results land in stages.
